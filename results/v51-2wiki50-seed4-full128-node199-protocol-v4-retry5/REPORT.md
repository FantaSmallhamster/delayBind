# Protocol-v4 retry5: 2Wiki 128 题完整测试报告

本轮完整处理 seed=4 的 128 道 2Wiki 问题，每题 50 篇文档。128 题均生成可解析的最终答案，没有运行时错误、资源耗尽或 API 重试耗尽。

按冻结数据的 `answers[0]` 和上游 `exact_match_score` / `f1_score` 评分：**EM=52.34%（67/128），F1=59.21%**。其中 67 题 F1=1，43 题 F1=0，18 题获得部分 F1。

## 固定配置

- 数据：`data/test/seed4/eval_2wikimultihopqa_50.json`，SHA-256 为 `24bf5d18ce3911d05e4ad3666e9836adfbb1e73e436a146e55d436cec2a8e576`。
- 128 题、每题 50 文档；119 题读取 2 个窗口，9 题读取 1 个窗口，共 247 个窗口。
- 模型：`Qwen/Qwen3.5-9B`；窗口大小 5000 tokenizer tokens；样本并发数 1。
- `temperature=0.7`、`top_p=0.95`、`enable_thinking=false`、`max_output_tokens=10000`，不传模型 seed。
- API 单次超时 120 秒，`api_max_retries=5`，即首次请求加最多 5 次重试。
- API 域名为 `https://api.siliconflow.cn/v1`；成功请求的实际连接 IP 均为 `47.239.215.199`，保留原域名、SNI 和 TLS 证书校验。
- 高层 agent 执行 PLAN、MEMORY、ANSWER；低层 agent 执行 UPDATE、RECALL、VERIFY。
- 使用 protocol-v4 的自然语言事实、依赖子 query、工作记忆和 defer workspace 流程。
- 运行中未修改代码、提示词、数据、模型参数或抽样范围；审计确认源码与 `code_snapshot/` 一致。

该 seed4 数据没有对应的已跑 baseline，因此本报告不与旧 seed42 baseline 或 ReMemR1 论文分数直接配对。论文作者使用的精确题目和上下文身份仍未得到验证。

| 问题类型 | 数量 | EM | F1 |
| --- | ---: | ---: | ---: |
| comparison | 38 | 84.21% | 84.21% |
| bridge_comparison | 32 | 75.00% | 75.00% |

比较类问题明显好于 compositional 和 inference。这个差距说明主要瓶颈仍在多跳计划、实体/关系绑定和关键证据收集，而不是最终的日期或数值比较本身。

## API 重试结果

- 总请求尝试 1211 次，其中成功 1144 次、失败尝试 67 次；56 个逻辑调用至少失败过一次，最终全部恢复。
- 失败包括 37 次读取超时、22 次 HTTP 500、8 次 HTTP 503 服务繁忙。
- 1088 个逻辑调用首次成功；48 个在第 2 次成功；5 个在第 3 次成功；3 个在第 4 次成功。
- 没有调用需要第 5 或第 6 次尝试，也没有 API 重试耗尽。

三条调用只有增加重试次数后才能完成：

| 样本 | 接口 | 前三次失败 | 成功尝试 |
| --- | --- | --- | ---: |
| dev_6942 | RECALL | 500、500、超时 | 4 |
| dev_1088 | MEMORY | 超时、503、超时 | 4 |
| dev_5288 | UPDATE | 超时、超时、超时 | 4 |

原配置最多只有 3 次总尝试，因此这三条调用会重试耗尽。`api_max_retries=5` 对本轮全量执行产生了实际作用。

## 协议与格式

- 111/128 题严格协议有效；17 题至少发生一次 `PROTOCOL_REPAIR_EXHAUSTED`。
- 共 20 次协议修复耗尽：UPDATE 9 次、MEMORY 8 次、RECALL 3 次。
- 103 次模型输出未通过首次解析或校验：UPDATE 63、MEMORY 28、RECALL 10、PLAN 1、VERIFY 1。
- UPDATE 发起 54 次局部修复，其中 45 次修复成功，9 次耗尽后保留已通过校验的事实继续运行。
- 拒绝 119 行 UPDATE、39 行 MEMORY；忽略 34 行明确空占位或无结果说明。
- 99 次过早绑定被暂缓，61 条不满足证据、query 状态或支持引用要求的记忆命令被拒绝。
- 没有 `FACT_SKIPPED` 静默跳过记录。

严格协议有效题的 EM 为 53.15%、F1 为 60.05%；协议无效题的 EM 为 47.06%、F1 为 53.73%。格式回退与较低分数相关，但不是本轮准确率问题的唯一来源。

## Defer 与 VERIFY

- 168 次 defer workspace 查找与候选扫描；101 次恢复所选候选对应的已读原文。
- 共验证 105 个候选：71 MATCH、18 MISMATCH、10 UNCERTAIN、6 CONFLICT。
- 71 个 MATCH 事实被提升，其中 6 个是跨窗口提升。
- 审计确认 VERIFY 只处理当前 defer 查找中选中的候选，恢复的原文只来自这些候选的 `source_refs`，且均已在之前的阅读窗口出现。
- 审计也确认失效事实在上游绑定纠正后可以保留，并在新绑定触发时重新作为候选审查；没有越过 defer 选择直接提升。

本轮覆盖了此前 8 题冒烟没有覆盖到的真实跨窗口提升路径，但事件链路正确不等于候选事实或模型判定在语义上一定正确。

## 工作记忆与回答限制

- 共保存 496 个事实节点，发生 324 次直接接受、183 次 defer 使用、360 次 query 绑定和 71 次事实提升。它们是不同用途和状态事件，不能相加视为唯一事实数。
- ANSWER 后仍有 29 题存在未解决子 query，共 57 个未解决 query。这符合当前“文本结束后跳过充分性检查，直接 ANSWER”的设计。
- 当前 boxed ANSWER 只检查输出格式，无法证明回答仅使用工作记忆。模型仍可能用自身知识补齐缺失日期或实体属性；本轮没有为 128 题逐条进行答案支持性裁判。
- ACTIVE 事实按当前用户确认的流程直接进入工作记忆，不经过 VERIFY。因此来源编号合法仍不能阻止实体混淆、关系方向错误或事实正文与原文不一致。
- 已知 `dev_1476` 标注异常仍原样保留：问题询问国籍，但冻结首个金标是电影名 `Chill Factor`。核对原始 JSONL 后确认异常来自源数据，本轮未更换金标或调整分数。

因此，**52.34% EM 是当前冻结评分协议下的最终答案分数，不是“完整证据链正确率”**。证据链完整性需要单独的支持性评估。
