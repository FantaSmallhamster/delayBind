## 二、17 道 PLAN 硬失败：比较叶子先被校验，后才有机会清理

17 道全是比较题。模型在两侧证据查询之后又增加 Q3/Q5 一类“哪部电影更早／导演更年轻”的最终计算节点。该节点依赖上游查询，却没有在自身 `query` 模板中引用相应 `?变量`，于是 `text_protocol_v52.parse_plan` 抛出 `DEPENDENCY_TEMPLATE_MISMATCH`。`subquery_runner_r2` 目前调用 `parse_plan(raw)` 成功后才调用 `normalize_evidence_collection_plan(...)`；因此原本应交给 ANSWER 的冗余叶子还没来得及清除，整个 PLAN 已失败。PLAN 重试一次后仍给出同型节点，17 题没有进入 UPDATE。

典型例子 `dev_9742`：Q1/Q2 找两部电影的导演，Q3/Q4 找导演生日，Q5 再问“哪部电影的导演出生更晚”，`depends_on: Q3,Q4`。Q5 应是 ANSWER 的比较操作，不能让它使四个有效证据查询失效。`dev_6203` 的电影上映先后也一样。

题号：`dev_10404`, `dev_10994`, `dev_11285`, `dev_12150`, `dev_12160`, `dev_2020`, `dev_2261`, `dev_4865`, `dev_5667`, `dev_6203`, `dev_7221`, `dev_7692`, `dev_8009`, `dev_9193`, `dev_9212`, `dev_9348`, `dev_9742`。

## 三、24 道运行错误：23 道 MEMORY 协议／修复耗尽，1 道 UPDATE 连续超时

23 道的最终错误来自 MEMORY：

- 20 道是 `INVALID_FACT_ONLY_MEMORY_FIELD`：其中 7 道直接输出 `NONE`，而协议要求无动作时输出 `NOOP`；另 13 道输出 `值 | F1` 等，漏掉 `BOUND |`。例如 `dev_11153` 对已有绑定先输出 `NONE`，修复调用仍输出 `NONE`；`dev_4961` 输出 `Singeetham Srinivasa Rao | F1`，修复仍缺 `BOUND |`。
- 3 道是 `INFERRED_ONLY_FOR_INTERMEDIATE_QUERY`：试图用 `BOUND | 值 | NONE` 给中间查询建立无直接事实支持的绑定，如 `dev_3792`。`NONE` 作为支持字段并非任意免证通行证。
- 修复提示主要传递机器错误码和被拒文本，未把“`NONE` 应改成 `NOOP`”或“缺少 `BOUND |` 前缀”翻译成明确的本次修复目标；轨迹中多次可见原样重复。

第 24 道 `dev_2271` 是 UPDATE 连续三次读取超时后退出，属于 API/传输故障，不能归入 MEMORY 语义问题。

本轮所有模型调用记录中，共有 94 次 `The read operation timed out` 和 8 次 HTTP 503 尝试，涉及 65 道题；多数经重试继续完成。因此“接口有波动”属实，但不能用它解释其余 82 道未匹配题，也不能把 23 道 MEMORY 协议错误称为 API 超时。

MEMORY 错误题号：`dev_1060`, `dev_11153`, `dev_1328`, `dev_1456`, `dev_2828`, `dev_2959`, `dev_3133`, `dev_3792`, `dev_3890`, `dev_4021`, `dev_4237`, `dev_4298`, `dev_4961`, `dev_5416`, `dev_5776`, `dev_5885`, `dev_6782`, `dev_7217`, `dev_729`, `dev_738`, `dev_768`, `dev_8491`, `dev_9001`。

## 六、优先级与验证建议

1. **先消除无谓硬失败。** 让 PLAN 在完整依赖校验前识别并移除可明确判定的最终比较／计数叶子，仍保留 PLAN 只负责收集证据的职责；其余非法 DAG 应继续报具体错误。再让 MEMORY 修复提示明确指出缺少 `BOUND |` 或应使用 `NOOP`，并用独立 MEMORY 对照测试验证。仅这两处就覆盖本轮 40 道硬失败，但不保证这些题最终都会答对。
2. **再抓关键证据与角色一致性。** 对 UPDATE 的出生地／死亡地／国籍／亲属代际做逐条原文回归；阻止把电影年份当人物出生年、把父亲当国籍、把当前一跳的实体当下一跳答案。MEMORY 的绑定值也要与当前实例化问题的角色匹配，特别是逆表达与亲属两跳。
3. **单测 ANSWER 的确定性比较。** `dev_2943`, `dev_4680`, `dev_954` 的必要工作记忆基本已经具备，适合固定输入重放，而不是重跑 128 题找问题。
4. **分离模型错误与基准问题。** 至少 `dev_10191`, `dev_11630`, `dev_4020`, `dev_4060`, `dev_4478`, `dev_5027`, `dev_6901` 的标准答案与提供的原文存在缺证或关系不符；另有上表 7 道别名／粒度不匹配。应保留原始严格 EM，同时增加人工审计标记或受控等价评估，不能靠提示词逼模型输出原文不支持的答案。

统计口径：`results.jsonl` 的 `answer_exact`、`runtime_status` 与每题 `trajectory_path`；原文来自同一冻结数据文件的 `context`。本报告的“首个关键失真”是基于轨迹的诊断，不等于对该题所有潜在问题的穷尽证明。
