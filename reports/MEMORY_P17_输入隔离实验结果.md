# MEMORY 输入隔离、短提示词与后续链路验证

日期：2026-09-21。分支：`solitary-dingo`。

## 结论

本轮已经完成实验代码、两个阶段的独立 MEMORY 验证，以及满足新快照收益条件后的有限下游联调。**P17-full 明显减少了漏绑，但也引入了反证误绑和结果值污染，因此没有替换生产默认 B。**

UPDATE、PLAN、既有 A/B 提示词、基数、REBIND、绑定事务、分句开关及 syntok 均保持不变。新增提示词和 renderer 只由实验入口使用。候选诊断的 JSON 不进入生产协议，也不提交运行时。

不能再把问题简单归结为“MEMORY 太保守”：本轮同时观察到原问题干扰、角色方向误判、必要支持遗漏、多值决策错误和输出值粒度错误。UPDATE 缺少必要事实的问题也不会因为 MEMORY 更积极而消失。

## 验证规模与口径

- 第一阶段：78 个条件，各固定 3 次，共 234 次回答。
- 独立候选诊断：6 个条件，各 3 次，共 18 次回答。
- 第二阶段：旧 55 项回归和新增 30 项条件，B/P17-full 各 3 次，共 510 次回答。
- 合计 762 次独立 MEMORY/诊断回答，全部计入，没有挑选最好的一次。三次重复不是三道独立题。
- 新验证来自旧八题以外的 12 个问题家族，加一个完全合成的作品名称家族。历史 V5.1 MEMORY 中的可见事实被投影为单查询 R2 快照；不是原生 R2 历史轨迹。派生扰动全部显式标记，不注入最终金标。
- 第三阶段另对 4 道代表题进行 B/P17-full 配对下游联调，各一次。冻结原始 PLAN 和逐窗口 UPDATE 输出，真实调用 RECALL、MEMORY、ANSWER，真实执行激活与绑定事务。不是八题全量 EM，也没有重新测试 UPDATE 抽取质量。

模型参数始终为 Qwen/Qwen3.5-9B、temperature=0、top_p=0.95、enable_thinking=false、max_tokens=10000。没有进行 thinking 配置实验。

## 一、第一阶段：哪些因素确实影响了结果

### 1. 同一组 19 个核心条件

| 版本 | 完全正确 | 正确绑定/应绑定 | 正确 NOOP/应 NOOP | 错值/误绑且通过运行时 | 另被解析器拦截的多值提议 | 家族宏平均正确率 |
|---|---:|---:|---:|---:|---:|---:|
| B | 37/57 | 16/36 | 21/21 | 0 | 0 | 72.22% |
| P17-full | 48/57 | 27/36 | 21/21 | 0 | 0 | 91.67% |
| P17-local | 48/57 | 30/36 | 18/21 | 4 | 3 | 77.78% |

P17-local 虽然绑定更多，但把 Georg Ernst 当成其父亲/父母的答案共 4 次；在 Taras Bulba 的 SINGLE 查询上，3 次把两个导演拼成一个字符串，均被现有解析器拒绝。因此没有选择它进入第二阶段。

按调用前固定的“零误绑优先、再比较家族宏平均”的标准，冻结 P17-full 进入第二阶段。此时未根据观察结果再修改提示词。

### 2. A-neutral：近重复示例不是本轮回退的充分解释

在同样的 6 个重点快照、每项 3 次的配对条件下：

| A | A-neutral | B |
|---:|---:|---:|
| 6/18 | 12/18 | 7/18 |

dev_5343 的带头衔及裸名条件中，A 与 A-neutral 均为 3/3 正确。没有观察到移除真实姓名示例后这道题退化；反而 A-neutral 在 Yamata 原始事实和 Mary 丈夫快照上改善。

这说明示例专名会影响当前提示词的行为，但不能把 A 的优势统一归因为“记住了测试题姓名”，也不能据此宣称 A-neutral 已全面优于 B。这只是在预选的六个条件上的结果。

### 3. 原问题展示的干扰，比变量改名更有解释力

保留 B 的提示词，只改动态输入展示。每格是正确次数/3：

| 条件 | 展示原问题 | 展示输出变量 | dev_10616 parent | dev_4961 director |
|---|---|---|---:|---:|
| D00 | 是 | 原变量 | 0/3 | 0/3 |
| D10 | 否 | 原变量 | 3/3 | 3/3 |
| D01 | 是 | `?result` | 0/3 | 0/3 |
| D11 | 否 | `?result` | 3/3 | 3/3 |

在这两个当前查询已完整实例化的快照中，隐藏原问题稳定恢复了正确绑定；仅改变量名没有恢复。这支持“全局问题与当前子问题竞争”的解释，但不意味着所有查询都可以删除原问题中的时间、范围或指代约束。

P17-local 不等于单独 D10：它还更换了指令、删除其他分区，并调整了字段展示。因此不能把 P17-local 的错误反过来当成 D10 无效。

### 4. 顺序、短 ID、词面重叠

Yamata 的 I00/I10/I01/I11 四种条件分别固定原序/反序及正确事实 F2/F1；四种在 B 下都为 0/3。短 ID 修改不会改变行序；反序不会重新编号；评分先还原持久 ID。

仅把错电影 Fanny and Alexander 换为 Silver Harbor，仍为 0/3。**这轮没有证据证明单独改变顺序、编号或该词面重叠就能修复原始失败。**

固定旧 F1/F2、把新增噪声放在 F3 后，错实体噪声条件为 1/3，错关系噪声条件为 3/3。上一轮“加噪声反而成功”并不是对所有噪声都稳定成立；旧实验还混入了 ID 重排，不能据此认定原因只有相关性过滤。

### 5. 姓名中的逗号不是唯一原因

dev_5343 中 B 对完整头衔为 1/3，对去掉答案头衔的裸名为 0/3；P17-full 对两者均为 3/3。移除逗号没有单独修复 B。

仍保留真实多实体 NOOP 负例，没有增加“删除逗号/and”这样的启发式修补。单个作品名含 and 的新验证也与真正两个作品分别标注。

## 二、独立候选诊断：可观察，但还不安全

诊断使用单独请求，只输出候选、支持、排除项、反证和决策；不向运行时提交。以下每项均重复 3 次：

| 条件 | 观察 |
|---|---|
| 直接父亲事实 | 3/3 正确提取 Jobst 并 BOUND |
| son-of 查询 parent | 3/3 正确提取 Jobst 并 BOUND |
| son-of 加男性角色证据 | 找到 Jobst，但 3/3 只引用 F1，遗漏必要角色事实 F2；不算通过 |
| 只有 son-of，却查询 father | 3/3 错误 BOUND，缺少角色依据仍未被正确处理 |
| SINGLE 下两个导演 | 3/3 分出了两个正确候选，却仍输出 BOUND；决策层错误非常明确 |
| 只有错电影事实 | 3/3 决策 NOOP 正确，但没有在排除列表报告该事实，诊断记录不完整 |

最后两类“不完整记录”不是 JSON 语法错误。原结果文件保留初始校验标签；`diagnostic_audit.json` 补充具体缺失 ID，且确认成功/失败判定未变。

独立诊断能回答部分“候选是否能被提取”的问题，但它的成功不能证明旧 NOOP 请求内部已经找到了候选。它同时暴露了角色语义和最终基数决策的错误，不能直接作为生产发布器。

## 三、第二阶段：新快照有收益，但旧回归出现安全退化

| 数据 | 版本 | 完全正确 | 正确绑定/应绑定 | 正确 NOOP/应 NOOP | 错值/误绑 | 家族宏平均 |
|---|---|---:|---:|---:|---:|---:|
| 旧 55 项 × 3 | B | 136/165 | 91/120 | 45/45 | 0 | 82.74% |
| 旧 55 项 × 3 | P17-full | 150/165 | 108/120 | 42/45 | 6 | 90.00% |
| 新 30 项 × 3 | B | 58/90 | 37/69 | 21/21 | 0 | 66.03% |
| 新 30 项 × 3 | P17-full | 84/90 | 63/69 | 21/21 | 0 | 96.15% |

去掉完全合成的作品家族，仅看其他 12 个历史问题及其派生对照：B 为 55/84、家族宏平均 67.36%；P17-full 为 78/84、95.83%。因此观察到的新快照收益并非仅由合成作品例子贡献。

旧回归中 P17-full 新增的 6 次错误是两个条件各 3 次：

1. `dev_5343.Q1.1.counterevidence`：同时给出 husband 支持和明确否定，仍绑定 Richard，忽略反证。
2. `dev_91.Q2.1`：应绑定机构，却输出 `Thorvald Stoltenberg works at the Norwegian government` 整个事实句。字段数和事实 ID 都合法，现有运行时仍会接收，不能把格式有效等同于语义正确。

它另外在 dev_5343 母亲的历史快照、dev_10616 parent/男性角色组合上各漏绑 3 次。新快照的 6 次失败也集中于 Gulussa 的 parent 和两事实 father 条件；关系逆转和角色组合仍未解决。

### 顺序/ID/噪声稳定性

三个新问题家族，各有反序、仅换 ID、增加无关事实三种扰动，各重复 3 次，总计 27 对：

| 版本 | 决策、值、持久支持集合保持一致 | 基例与扰动都正确 |
|---|---:|---:|
| B | 16/27 | 12/27 |
| P17-full | 27/27 | 27/27 |

一致性使用持久 ID，而不是比较表面 F1/F2。B 的一致性高于双方都正确的数量，说明稳定的错误 NOOP 不能算成功。

## 四、有限第三阶段：真实新增下游调用

由于 P17-full 在新快照上有净收益，进一步进行了隔离链路联调。生产没有切换。每个版本从新的运行时数据库开始，冻结相同 PLAN、相同原文窗口和 UPDATE 抽取结果，随后真实运行后续调用，没有替换旧 MEMORY 输出伪造新轨迹。

| 问题 | B 本次链路 | P17-full 本次链路 | 含义 |
|---|---|---|---|
| dev_7920 | 丈夫和出生日期均绑定；回答 26 May 1968 | 同左 | 已修复路径保持可用 |
| dev_4961 | 导演未绑定；UNKNOWN | 导演绑定 Alexander Korda，触发 RECALL 和新的下游 MEMORY；最终仍 UNKNOWN | 冻结事实只有死亡年份，没有死亡地点；积极绑定不能补出缺失事实 |
| dev_5343 | 丈夫未绑定；UNKNOWN | 丈夫、母亲均绑定；回答 Elizabeth Woodville | 实际出现了原 B 轨迹中不存在的下游调用 |
| dev_91 | 机构值绑定为 the Norwegian government | 机构槽错误绑定整条事实句，但 ANSWER 仍输出 the Norwegian government | 最终输出正常可能掩盖内部绑定值污染；也不能据此证明原题金标正确 |

这些是可见事实约束下的联调观察，不报告八题 EM。所有有效轨迹的事务重放一致性均为 1。

还有一个重要稳定性信号：dev_5343 的母亲查询在第二阶段 3 次 NOOP，第三阶段却 BOUND；核对后模型消息完全相同、API 参数相同。这是跨批次调用差异，不能虚构为“输入因状态推进发生变化”。temperature=0 也未使本次服务的所有调用严格复现。

### 实验接线错误及恢复记录

第三阶段首轮的实验包装只允许低层 UPDATE，误把同属低层的 RECALL 拦截，导致 6 条轨迹在新增下游调用时中断。这是本轮新增实验代码的问题，不是生产 runtime 或模型失败。

已修复为“只冻结 UPDATE，RECALL 转发真实 API”，并添加专项测试。原 `stage3/` 日志完整保留；首轮已经有效完成的 2 条 B 轨迹未重采样，另外 6 条在 `stage3-recall-routing-fix/` 重新启动。汇总中显式标注沿用的有效轨迹，不选取多个答案中的较好者。

## 五、当前代码与下一步判断

当前保持 B 为生产默认；没有把 P17-full 或 JSON 候选诊断上线。

新增入口与职责：

- `delaybind_core/prompts_r2.py`：增加 A-neutral、P17 和候选诊断常量；既有生产 dispatch 不变。
- `delaybind_core/memory_experiments_r2.py`：实验专用展示、别名和顺序控制；不被生产 runner 导入。
- `scripts/evaluate_r2_memory_isolation.py`：冻结条件、固定重复、缓存旁路、映射评分、诊断、选型、完整回归与审计。
- `scripts/evaluate_r2_memory_chain.py`：冻结 PLAN/UPDATE 的实际下游联调，独立数据库和进程内实验提示词覆盖。
- `tests/fixtures/r2_memory_ab/isolation_annotations.py`：新题目来源、可见事实标签、重复数、预定选型规则。
- `tests/test_r2_memory_isolation.py`：显示不改图、顺序/ID 独立、诊断不入库、冻结抽取不冻结 RECALL 等检查。

原 `evaluate_r2_memory_ab.py` 和生产 `subquery_runner_r2.py` 文件保持冻结；新功能用独立模块实现，避免改变上一轮可复现基线。

建议下一轮优先验证 **B 仅隐藏冗余原问题的局部输入方案**，扩展到完整正负例和新题目，前提是当前 query 已承载所有必要约束。P17-full 需先解决“保留真正反证”和“只输出当前结果值”的退化，再考虑替换默认。候选结构化可以继续用于诊断，但不能把语义判定的错误推给基数规则自动解决。

## 六、审计与复现

本地测试：**442 passed**。762 条独立 MEMORY/诊断记录全部重新核算，结果与原评分一致；冻结文件、输入条件、提示词及真实 API 参数检查通过，缓存命中为 0，诊断运行时提交为 0。

前两阶段及诊断共 763 次 HTTP 尝试，得到 762 个回答；有 1 次 TLS EOF，在同一次逻辑调用内部自动重试恢复，无未完成请求，无 500/503/超时失败。包含第三阶段及其已记录的接线失败尝试，本轮合计 804 次 HTTP 尝试、803 个模型回答，输入约 797,279 tokens、输出 6,793 tokens；未隐去实验失败成本。
