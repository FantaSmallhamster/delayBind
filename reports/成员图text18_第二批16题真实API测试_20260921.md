## 题目质量核查

### 明确存在材料/金标问题：2 题

`dev_1328` 的正文明确写 Ragnall Guthfrithson 是 Gofraid ua Ímair 的儿子，也写 Gofraid 于 934 年因病去世，但没有写死亡地点是 Dublin。Dublin 是其统治地。另一个同名人物 Gofraid mac Arailt 的死亡情况被写为不明。因此金标 Dublin 缺少直接正文支持。

`dev_5027` 的正文写 Henry de Percy 获授 Warkworth 的城堡和领地，但没有写他死于 Warkworth。金标把关联地点当成死亡地点，正文支持不足。

### 边界性近似答案：1 题

`dev_10526` 的正文是 Adolf died in the Battle of Göllheim。模型绑定并回答 `Battle of Göllheim`，金标是地点 `Göllheim`。它不是严格相同的答案类型，但包含正确地点，可视为规范化近失，不是完全没有找到答案。

其余 13 题中，金标实体或值均出现在正文；抽查失败题的关系链后，至少 11 题有足够直接材料。本批不能支持“主要是题目有问题”的判断。

## 框架错误分析

### 1. UPDATE 是最大误差来源

`dev_2065` 的首个 UPDATE 输入已经包含 `Sir James Power (6 December 1800...)`，但只输出父子关系，没有输出生日。随后 MEMORY 面对生日问题返回父亲人名，并在修复后重复同一错误。

`dev_1850` 第一窗口把配偶抽成自指事实：

```text
Constantin J. David's spouse is the spouse of Constantin J. David.
```

第二窗口实际包含 Käthe von Nagy，却返回 `NONE`。

`dev_8904` 第一窗口没有 Newport，却将 Boston（出生地）写成死亡地；第二窗口包含明确的 `died ... in Newport, Rhode Island`，UPDATE 却返回 `NONE`。

`dev_2955` 第一窗口包含 `born in Hradec Králové`，UPDATE 返回 `NONE`；第二窗口没有 Hradec Králové，却输出更粗的 Czechoslovakia。

这与上一批 Lana Del Rey 的错误模式一致：**准确事实在早期窗口被漏掉，后续窗口又生成错误或低精度事实。** 当前逐窗口 UPDATE 没有可靠地保存尚未实例化的下游事实。

### 2. MEMORY 会选中不回答当前 query 的值

- `dev_1328` 问死亡地点，MEMORY 绑定 `934`。
- `dev_2065` 问生日，MEMORY 绑定 `James Power`。
- `dev_5132` 问父亲，MEMORY 从“Henry 是 William 的父亲”中绑定 `William II`；下一跳又试图无直接事实绑定 George Louis。
- `dev_1850` 将 `Constantin J. David's spouse` 这种占位短语当作具体配偶。

说明当前 runtime 主要验证“值是标量、事实 ID 可见”，没有验证“该值在事实中的语义角色能回答当前 query”。

### 3. MEMORY_REPAIR 仍不能稳定恢复格式和语义错误

4 题以 MEMORY 协议错误结束：

- `dev_1328` 的 REBIND 两行均漏写 `BOUND`，修复后原样重复。
- `dev_6188` 输出 `NONE`，协议要求 `NOOP`；修复后仍是 `NONE`。
- `dev_2065` 和 `dev_5132` 使用 `NONE` 支持不成立的下游结果，修复仍重复错误。

这些都不是 API 服务错误，而是 repair 提示没有让模型稳定完成指定修正。

### 4. PLAN 有两类问题

`dev_3890` 只需要“父亲＋死因”，PLAN 却增加死亡日期、配偶和政治背景，共 5 个节点。正确的 firing-squad 事实已经绑定，但重复扫描和重绑定最终触发 `FINAL_FACT_MEMORY_BUDGET`。

`dev_9742` 的 PLAN 添加了最终比较节点 Q5。当前架构要求比较由 ANSWER 完成，runtime 拒绝该依赖模板；PLAN_REPAIR 仍返回相同结构，最终 `PLAN_PROTOCOL_ERROR:DEPENDENCY_TEMPLATE_MISMATCH`。

### 5. 最终答案阶段不是本批主要问题

本批能进入 ANSWER 的 10 题中，5 题严格正确；`dev_10526` 是值规范化近失，`dev_8904` 和 `dev_2955` 是沿着错误的 UPDATE/MEMORY 事实作答，`dev_1850` 和 `dev_5027` 输出 UNKNOWN。没有出现上一批国籍题那种“正确工作记忆齐全但比较答错”的明确案例。
