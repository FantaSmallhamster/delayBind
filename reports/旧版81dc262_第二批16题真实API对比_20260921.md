# 旧版 81dc262：第二批 16 题真实 API 测试与对比

## 结论

使用 Git commit `81dc262a22e523cd36113b8e3d8c9d9f544dc6ed`（`Add frozen filtered 2Wiki benchmark`）的原始 V5.1 框架，对与当前版相同的第 9–24 条 16 题进行真实 API 测试。

旧版严格答案准确率为 **5/16（31.25%）**，与当前 member-graph text-18 版本完全相同。旧版答案 token F1 为 0.4226，当前版为 0.34375。

两版的失败形态明显不同：

- 旧版 16/16 都生成最终答案，没有 runtime/resource/plan 终止；但会接受错抽事实、无来源推断和错误重绑定，部分答案是“顺利答错”。
- 当前版只有 10/16 调用 ANSWER，其中 8 题得到非 UNKNOWN 答案、2 题为 UNKNOWN；另外有 4 个 MEMORY runtime error、1 个资源上限和 1 个 PLAN error。严格性提高，但运行稳定性显著下降。
- 两版都答对的只有 3 题，说明相同总分掩盖了不同的错误路径。

## 运行边界

- 独立临时 Git worktree，detached HEAD 精确为 `81dc262a22e523cd36113b8e3d8c9d9f544dc6ed`。
- 没有加载当前 R2 源码、提示词、成员图或当前配置。
- 使用该提交自带的 V5.1 配置参数：temperature=0.7、top_p=0.95、model seed 未指定、API 最多重试 5 次、timeout=120 秒、chunk_size=5000、memory budget=8192。
- 仅将样本范围改为 `sample_start=8, sample_count=16`，并使用全新输出目录。
- 模型与 API 地址仍为 `Qwen/Qwen3.5-9B`、`https://api.siliconflow.cn/v1`。
- 当前版测试使用 temperature=0、API 最多重试 2 次，因此这是“各版本按自身配置”的复现实验，不是只改变代码的严格单变量 A/B。

## 旧版为何能 16/16 生成答案

旧版协议更宽松，对模型生成的绑定值缺少严格的角色、来源和事务约束。它因此避免了当前版的协议中断，但也允许错误事实持续进入工作记忆。

### 无支持命中也会计分

`dev_1328` 的原文只说 Gofraid ua Ímair 统治 Dublin、于 934 年因病去世，没有写死于 Dublin。旧版 UPDATE 生成了两条“Ragnall 父亲死于 Dublin”的事实，最终回答 Dublin 并命中金标。这证明 EM 命中不等于证据链正确。

### VERIFY 不能稳定阻止错误，甚至会破坏正确候选

`dev_4167` 的 UPDATE 已生成正确生日 `17 January 1881`。VERIFY 判定候选 MISMATCH 后，MEMORY 又绑定 1942，最终回答工作记忆中不可得。当前版在该题正确。

`dev_1850` 的第二窗口正文明确包含 Käthe von Nagy。旧版没有抽到，VERIFY/后续 MEMORY 反复生成“spouse not mentioned”，最后回答 Unknown。

### 宽松绑定导致“有答案但语义错误”

- `dev_8904`：将 James Franklin 的死亡地点回答为 Philadelphia；正文明确是 Newport。
- `dev_2955`：将 Otakar Vávra 出生地回答为 Prague；正文明确是 Hradec Králové。
- `dev_5132`：祖父回答 Count John V；正文链路指向 George Louis。
- `dev_9742`：工作记忆使用错误出生年份并回答 Atheetham；正文年份比较应得到 Otec neznámý。

### 输出规范化不足损失严格 EM

`dev_3890` 输出 `He was executed by firing squad on December 25, 1989`，在语义上回答了死因，但严格金标是 `execution by firing squad` / `firing squad`，因此官方计错。旧版 token F1 高于当前版，部分来自这种包含答案但过长的输出。

## 判断

旧版不是明显更准确：它与当前版严格 EM 相同，并且唯一多出来的 `dev_1328` 正确题缺少原文支持。旧版的优势是流程容错和最终覆盖率，缺点是错误事实容易穿透到答案；当前版的优势是更明确的图和约束、部分关系题更准确、成本更低，缺点是协议修复、PLAN 和资源控制造成大量提前失败。

因此下一步不应整体回退到旧版。更合理的方向是保留当前成员图和职责划分，同时恢复旧版的运行韧性：让格式修复确定化、避免模型负责可由 runtime 补齐的动作字段、限制 PLAN 过度展开，并增加 query-answer 角色校验。
