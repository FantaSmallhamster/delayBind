# MEMORY 三项改进与隔离验证

日期：2026-09-22。分支：`solitary-dingo`。本轮未修改 PLAN、UPDATE、RECALL 或 ANSWER 的逻辑，也未提交或推送。

## 已实施

1. 事实模式 FINAL 中，只有整条回复去掉首尾空白后严格等于 `NONE`，才规范化为 `NOOP`。事务事件 `MEMORY_FORMAT_NORMALIZED` 保留完整原始回复与规范化结果；恢复重放不会重复记账。混合 `NONE` 与 `BOUND`、代码块、大小写变体不纳入兼容。`BOUND | value | NONE` 的支持字段语义不变。
2. 成员模式的 MEMORY_REPAIR 继续展示原始错误码，同时指出缺少 `BOUND` 前缀、字段数量错误、未知事实 ID、缺少证明或混合命令等具体问题。程序不会替模型补出绑定。输入空状态改为描述性文本，旧绑定使用 `value=...; support=...`，降低照抄为两字段输出的风险。
3. 成员模式的事实 MEMORY 提示词区分首次绑定与重绑定，强调当前具体子问题有支持即可绑定，不等待后续问题完成；加入错关系、错实体与正确事实并存的正例，以及逆表达正例。当前分支没有旧绑定时，即使整体模式是 REBIND，也使用首次绑定规则。保留多成员、完整替代集合和旧绑定保护规则。

事实成员 MEMORY / MEMORY_REPAIR 的提示词版本为 `v5.2-r2-member-graph-text-21-memory-contract`。其他接口继续使用自己的版本。原文核验模式与旧非成员提示词保持不变。

## 本地验证

`python -m pytest -q tests`：**544 passed**。覆盖 NONE 审计、事务重放、候选保留、旧绑定保留、混合命令拒绝、支持字段 NONE 不被误替换、同一快照格式修复和未绑定分支的 REBIND。

仓库根目录直接运行 pytest 无法完成收集：训练及数据工具模块缺少 `torch`、`datasets`、`numpy`。未为本次 MEMORY 修改安装这些无关依赖，因此不声称整个仓库的全部测试通过。

## 真实 API：只测 MEMORY，不测端到端问答 EM

固定 8 个合成用例，事实与计划预先给定，使用真实解析器和状态提交校验最终成员及其事实归属。每个用例一次 MEMORY 请求，无协议修复或语义重采样。服务为项目现有配置 `Qwen/Qwen3.5-9B`，temperature=0，thinking=false。

| 用例 | 最终轮模型输出 | 结果 |
| --- | --- | --- |
| 直接表达 | `BOUND \| Rowan \| F1` | 通过 |
| 逆表达：Rowan 的母亲是 Mira，问 Mira 的孩子 | `NOOP` | 漏绑 |
| 只有错实体事实 | `NOOP` | 通过 |
| 只有错关系事实 | `NOOP` | 通过 |
| 正确事实与两类干扰并存 | `BOUND \| Rowan \| F3` | 通过 |
| Alice、Bob 两名成员 | `NOOP` | 漏绑全部成员 |
| 重绑定：无相关新增事实 | `BOUND \| Alice \| F2` | 通过，重申原值及证明 |
| 重绑定：新增 Bob 成员 | `BOUND \| Alice \| F2` | 只保留 Alice，遗漏 Bob |

最终结果：**5/8**；API 错误 **0**；协议错误 **0**；语义／成员状态错误 **3**。最终比较使用绑定值及其支持事实，不把格式合法的 NOOP 自动算作成功。

首轮真实 API 也是 5/8。之后补充“REBIND 中无旧绑定分支按 BIND 规则判断”并重新运行完整固定用例，仍为 5/8，两轮原始结果均保留。两轮未对失败用例单独采样后择优报告。

沙箱内另有一轮域名解析失败，8 次均未获得模型回复；它是运行环境连接失败，不计入模型语义准确率。获准联网后上述两轮没有 API 错误。

## 结论边界

三项实现及本地状态保护测试已完成。小规模真实测试未再出现格式错误，但不能据此认定历史 23 题协议失败均已修复，也不能声称 MEMORY 的语义漏绑已经解决。逆表达识别、全体成员提取和新增成员保留仍需针对性改进；本轮没有把合法 NOOP 强制改成 BOUND，也没有引入额外安全复核调用。
