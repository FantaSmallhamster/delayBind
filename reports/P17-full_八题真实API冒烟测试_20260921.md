# P17-full：八题真实 API 冒烟测试

## 结论

本轮八题全部完成，严格答案准确率 **1/8（12.5%）**，token F1 为 0.125。`dev_7920` 回答正确，其余七题均实际输出 `UNKNOWN`，不是运行中断后补填的失败答案。

只有一次 API 读超时，发生在 `dev_5343` 的 ANSWER；自动重试成功。未观察到 500/503 或最终 API 错误。因此，七题 UNKNOWN 不能解释为服务超时。

P17-full 在独立 MEMORY 快照上的改善没有转化为本轮端到端高正确率。原因同时涉及 UPDATE 漏抽/错抽、单值计划与多候选不匹配、MEMORY 漏绑、角色信息缺失及本次原文的答案支持不足，不能全部归结为 MEMORY 太保守。

## 逐题证据与归因

### dev_5343：明确的 MEMORY 漏绑

UPDATE 已提供两跳事实，Q1 成功绑定 Richard。RECALL 选中母亲事实，Q2 的实际请求包括：

```text
Current query: Who is Richard of Shrewsbury, 1st Duke of York's mother?
F1 | Richard of Shrewsbury, 1st Duke of York's mother is Elizabeth Woodville.
Effective upstream bindings: ?husband=Richard of Shrewsbury, 1st Duke of York
MEMORY output: NOOP
```

这是直接事实已到达正确查询后的漏绑，不是 UPDATE 未抽出，也不是缺少下游调用。最终 ANSWER 只看到了有效的丈夫事实，没有看到尚未接受的母亲候选。ANSWER 超时重试后仍回答 UNKNOWN。

### dev_4784：多导演、城市信息不足，不能强制任选一个

原文 Document 18 本身明确列出 Vladimir Strizhevsky 和 Joseph N. Ermolieff 两位导演。UPDATE 分别输出两条导演事实；PLAN 的导演查询仍为 SINGLE，MEMORY 返回 NOOP。

UPDATE 还输出两人出生在 Russia，但没有 Moscow 出生事实。核对本次完整 context，Moscow 出现在 Ermolieff 拥有电影制片厂的描述中，不是出生地；Strizhevsky 仅出现在影片导演名单中。故本题还存在给定文本与标准答案支持不足，不能把工厂所在地当出生地，或要求 MEMORY 凭空补齐。

### dev_11393：多演唱者与出生城市漏抽

原文 Document 48 提到 the Weeknd 和客串歌手 Lana Del Rey；UPDATE 为两人分别输出 performer 事实，引发 SINGLE 查询的多候选问题。

更明确的 UPDATE 问题是：Document 41 的 `Born in New York City` 确实进入了本次 UPDATE 请求，模型却只输出 `Lana Del Rey was born in the United States`。它没有保留可直接对应金标的城市信息。因此，即使绑定了 Lana，下游当前事实仍不够精确。

### dev_954：国籍多值与计划基数不匹配

UPDATE 输出 Ding 的 Chinese、German，以及 Lucae 的 German。MEMORY 对 Ding 返回 NOOP，对 Lucae 返回 `BOUND | German | F1`。

这不是格式错误：国籍有多个候选，而当前查询基数为 SINGLE。PLAN 还生成了比较节点 Q3；本轮忠实运行现有逻辑，没有改写计划。Ding 查询未绑定后，ANSWER 只获得有效的 Lucae 国籍，无法完成原问题。

### dev_91：遗漏工作机构，NOOP 不能直接算漏绑

丈夫 Thorvald 绑定成功。第二跳仅得到：

```text
Thorvald Stoltenberg worked as Minister of Foreign Affairs.
```

这是职位，不是明确的工作机构。原文 Document 48 中的 `United Nations High Commissioner for Refugees` 及其他 UN 任职内容确实进入了 UPDATE 请求，但未被抽取。本次 MEMORY 在缺少机构事实的情况下 NOOP，不能归为“已经有 United Nations 仍不肯绑定”。

### dev_10616：son-of 角色信息不足，另有非事实输出

第一窗口输出：

```text
Q1 | Georg Ernst of Limburg Stirum is the son of Jobst of Limburg.
Q2 | Jobst of Limburg is the son of Hermann Georg of Limburg.
```

MEMORY 对 Q1 返回 NOOP。这里不能仅凭 `A is the son of B` 就认定 B 必然是父亲：它明确的是 A 为男性子女，并未单独明确 B 的父亲角色。本次原文中的 count、he 等角色信息没有进入抽取后的事实，不能把全部问题都算成 MEMORY 不懂逆表达。

第二窗口 UPDATE 又输出 `Georg Ernst Of Limburg Stirum's father is not mentioned` 和 `?father's father is not mentioned`。这不是可用于回答问题的正向原文事实，还包含未实例化变量；当前运行时仍接收，Q1 第二次 NOOP。需要区分“关系角色信息丢失”和“窗口内未找到被写成事实”两类问题。

### dev_4961：错误抽取被信任，之后没有成功重绑定

第一窗口把另一部影片 Shravana Banthu 的导演误写为：

```text
Q1 | Singeetham Srinivasa Rao is the director of film Yamata.
Q2 | Singeetham Srinivasa Rao is the director of film Yamata.
```

P17-full 按收到的事实绑定了 Singeetham。该错误来自 UPDATE 的跨实体改写；FACT_ONLY MEMORY 不回看原文，不能自行知道这条看似直接支持的事实是错的。第二条还错误路由到死亡地点查询。

第二窗口出现正确导演 Alexander Korda 和死亡年份 1956。现有 REBIND 同时看到新旧两个导演事实，返回 NOOP，旧绑定继续有效；此处使用的是未替换的 REBIND 提示词，不是 P17 BIND。

核对 Document 42 和完整 context，现有材料没有明确提供 Korda 死于 London 的事实。London 仅出现在 London Films 及无关文档的奥运会描述中。因此，即使导演纠正，当前原文依据也不足以严格推出标准答案。

### dev_7920：链路成功，错关系事实被正确忽略

第一窗口误路由的是 Mary 父亲 John 的事实和生日，MEMORY 正确返回 NOOP，没有把父亲当丈夫。第二窗口得到 Frederik 的丈夫事实及生日，Q1 绑定 Frederik，RECALL 选中生日，Q2 绑定 `26 May 1968`，ANSWER 正确输出该日期。

- MEMORY 总输出：6 次 BOUND、10 次 NOOP。NOOP 既包含合理拒绝，也包含明确漏绑，不能直接把 NOOP 比率等同于错误率。
- 成功响应记录的 token 合计：输入 88,445，输出 1,286；超时请求未返回的服务端消耗无法由日志确认。
- 8/8 PLAN 格式有效；没有协议修复耗尽；汇总协议有效率 100%，事务重放一致性 100%。这些是运行完整性指标，不代表答案正确。
- 本地回归：444 项通过；新增测试验证仅替换 BIND 指令、完整输入不变、其他接口不变及 repair 接线一致。

## 如何解释这次结果

本轮没有同步运行生产 B 的全新八题对照，因此不能由 1/8 推出“P17 必然比 B 更差”。前面的 MEMORY 独立实验固定候选事实；本次 PLAN、UPDATE 均重新生成，错误会沿链路传播，衡量的不是同一个指标。

同时，当前 ANSWER 使用的是“有效工作记忆视图”，不是全部已抽取候选。`context_r2.evidence_pack` 会筛选 effective uses；例如 Anne 的母亲事实未被绑定后，不在最终输入里。因此“让 ANSWER 综合工作记忆”目前不意味着它能绕过 MEMORY 再审所有原始候选。这是本轮观察到的边界，未在测试过程中修改。

本轮只完成测试和归因，没有自动加入安全复核、改 PLAN、改 UPDATE、调整 MEMORY 或重采样失败题。
