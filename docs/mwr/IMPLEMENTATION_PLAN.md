# DelayBind-MWR：沿 Memorize-while-Reading 主线的详细修改与验收方案

## 文档性质与依据

这是针对 `v08_98of128_verify_step1.zip` 的**拟实施方案**，不是已实现的新版本，不代表模型实验已经通过。本轮重新读取了上传版核心代码和上一版修改方案；未修改原始源码、未调用模型、未重跑历史准确率。代码定位见同包 `SOURCE_MAP.md`。新增接口、状态、文件和配置均为建议，不能直接提交给 v08 当作现成配置使用。

研究内容沿用用户论文材料中的“查询需求—候选保留—延迟绑定—来源核验”组织方式。不新增全文检索器，不把阅读后的缺口改造成全局重读任务。本轮不对新文献覆盖或方法的新颖性作额外声明。

## 一、先固定研究主线和信息访问边界

### 1.1 要检验的主假设

> 在一次全局顺序阅读中，利用尚未满足的子问题所表达的关系需求，能否在相同记忆容量下保留更多用途后显的证据；当上游依赖明确后，再从存活记忆中召回这些证据、按已保留来源进行核验，从而改善最终问答及其成本？

重点是**阅读期间如何保留与更新**，不是回答时从全库重新找到答案。证据保留、候选召回、语义支持、最终利用是四个不同环节。

本方案的访问约束是为了隔离该假设而选择的实验协议，不宣称所有 Memorize-while-Reading 方法都必须遵守同一种回看限制。

### 1.2 本版本允许与禁止的操作

| 操作 | 本版本规则 | 对应职责 |
|---|---|---|
| 顺序读取下一个未读窗口 | 允许；游标只前进 | 首次发现证据 |
| 从存活候选中按查询、实体和关系筛选 | 允许；只访问当前保留集合 | 候选召回 |
| 按存活证据携带的来源指针取原文 | 允许；固定、受限、已读范围 | 核对来源和语义 |
| 必要的同文档邻近上下文 | 允许；固定上限、不递归、不跨已读边界 | 消解指代、限定范围 |
| 对完整原文档案按问题/实体搜索 | 禁止 | 不属于本版本方法 |
| 原文向量库、BM25、关键词补搜 | 禁止在新方法路径使用 | 可用于外部对照，不接入本方法 |
| EOF 后重新切窗、从头再读 | 禁止 | 不使用全局重读补救 |
| 从审计日志/历史快照恢复被淘汰语义 | 禁止 | 防止隐藏无限记忆 |
| 因缺证据而调用搜索或重读 | 禁止 | 如实记录缺口，继续尚未完成的前向阅读或结束 |

**一次全局扫描不等于每个 token 只看一次。**核验和作答允许局部指针回看，必须报告重复读取量。

**原文保留不等于线索保留。**档案可以仍在磁盘上；若相关语义索引和合法来源引用都已消失，系统不能通过全文搜索重新发现它。

还需处理一个例外：某条 cue 被删除，但另一条存活记忆仍合法指向同一来源，或固定邻域覆盖了该内容，此时来源并未完全不可达。因此分别统计“记录存活”“来源仍可达”和“候选被召回”，不能把一个 cue 的删除误报为全部信息丢失。

### 1.3 保留现有职责分工，不叠加新 Agent

低层继续负责当前窗口阅读、事实/线索提案，以及最终答案生成。高层继续负责计划、候选适用性审阅、绑定和依赖更新。运行时负责来源权限、存储、预算、事件调度和状态一致性。

保留查询计划 DAG 和工作记忆证据结构，但不把“所有节点必须先 RESOLVED”作为最终作答门槛。不新增检索 Agent、缺口补搜 Agent 或第二次全文阅读 Agent。

### 1.4 三条运行路径

`legacy_v08`：冻结旧实现，复现旧行为。

`flat_memory_mwr`：顺序阅读 + 预算内来源记忆 + 统一作答；不强制执行完整依赖图，用作简单强对照。

`delaybind_mwr`：需求引导保留 + 依赖触发候选召回 + 来源支持绑定。

旧 Graph 路径可以保留用于历史复现，但新路径不调用其原文搜索入口。不要为了“删除检索”破坏旧日志兼容。

## 当前已有能力与本次真正需要改变的部分

| 上传版已有 | 本次改变 | 不应写成的贡献 |
|---|---|---|
| UPDATE已看到active/dormant需求 | 减少泛化的过量抽取，增加可靠的候选接纳与预算化保留 | “首次想到让待解需求指导阅读” |
| RECALL只扫描候选，不查原文 | 统一未路由候选，限定到存活池并控制扫描成本 | “首次加入记忆召回” |

这些判断依据SOURCE_MAP中的C02～C05、C12～C14。它们是代码事实；新机制能否提升效果仍需实验。

## 二、数据模型：分清保留、适用性与来源权限

### 2.1 建议的状态

`S_t = (P_t, E_t, B_t, A_t, R_t)`。

`P_t`：计划及由当前绑定生成的需求视图。

`E_t`：当前持久保留的证据记录；已确认、延迟、未路由是其逻辑视图，不是三份相互隔离的正文副本。

`B_t`：有来源、带输入与版本的绑定及其依赖关系。

`A_t`：已读原文档案；只提供游标顺序读取和受限指针回看。

`R_t`：预算、游标、事件与必要的状态版本。

历史日志存在于审计域，不属于运行时可查询的语义记忆。

### 2.2 EvidenceRecord 建议字段

```text
EvidenceRecord:
  evidence_id
  source_spans[]             # doc_id, start, end, source_hash
  cue_text                   # 紧凑自然语言线索，不是未经核验的答案
  entity_mentions[]          # 可选，仅用于候选筛选
  relation_cues[]             # 可选，来自问题/原文，不要求固定关系本体
  candidate_query_ids[]      # 允许零个、一个或多个
  observed_window
  record_version
```

source span 身份不得由 query_id、窗口号或模型改写决定。一个 span 可以包含多个事实，不能简单强制“同一来源 = 同一事实”。建议分离稳定 `SourceSpanID` 与 `EvidenceID`；保留不同 claim，重复 claim 再去重。若无法可靠判等，宁可保留为不同线索并计算成本，不用有风险的自动合并抹掉限定。

### 2.3 三种状态必须独立

**保留状态**：RETAINED / EVICTED，回答“下一窗口还能否使用”。

**对具体查询实例的适用性**：UNASSESSED / RELEVANT_CANDIDATE / SUPPORTED / CONTRADICTED / INSUFFICIENT，回答“能否支持此主体的此关系”。

**查询就绪状态**：沿用 DORMANT / ACTIVE / RESOLVED 的界面语义，但不能把 DORMANT 等同于“不值得保留”，也不能把 ACCEPTED/RECALL 等同于“已通过语义证明”。

候选对 Q1 不适用，不应删除其对 Q2 的价值。来源忠实性和查询支持性必须分开。

### 2.4 计划与记忆共同更新，但只有一个绑定真相源

计划模板保留变量，例如 `Where was ?director born?`；成功绑定后，其实例化视图显示具体人物，同时工作记忆记录支持事实及上游路径。

不得把模板中的变量永久替换掉，再靠字符串回改。绑定值由一个 authoritative store 管理；查询视图与记忆视图在同一事件版本下生成，避免“计划改了、记忆没改”或反之。

上传代码的 QueryExecution 按 query 保存一个 result 和版本，不能声称已经实现论文材料中所有成员级绑定。第一版至少建立带输入指纹的实例作用域；集合/多结果必须记录成员支持，不能把一组不同父路径的属性展平成可随意组合的值列表。完整高阶组合求解可后续扩展，但所有样本继续报告，不能静默跳过不支持的题型。

## 三、分步骤实施与验收

## PR-00：冻结基线与新增 MWR 访问合同

**目的。**先保证新路径没有混入旧版全文搜索、重读和隐藏缓存。

**位置。**`runner.py::RunnerConfig/V5Runner.run`，`evaluation.py::ExperimentConfig/_run_condition`，`scripts/ultimate/run_experiment.py`；新增协议文档与新 engine 显式分派。[C01]

**具体修改。**

保存源码、提示词、配置、样本清单和 tokenizer 哈希。新结果使用独立 run_id、schema_version、输出目录；当前128题只作开发诊断。记录模型完整 ID、thinking、温度、输出长度、缓存策略。

新增 `engine=delaybind_mwr`，不能仅用 plan_format 或方法名称后缀隐式切换。新配置拒绝未知字段。对于新 engine，强制 `raw_search_enabled=false`、`global_reread_enabled=false`、`answer_gap_search_enabled=false`，而不是仅写在提示词里。

在测试中把 `RawArchive.search_mentions`、`expanded_context`、底层 `search_raw_mentions`、全文枚举接口替换为抛错桩；新路径端到端运行必须不触发。游标所需的原文入口和已授权 lookup 单独注入。

冻结旧测试；需要更新接口的用例明确迁移，不直接删除失败断言。运行脚本支持任意正整数样本数，进度以实际条件数计算。

**验收。**M01–M04。mock 完整流程、断点恢复和错误重试均不触发禁止接口；游标单调前进；版本变化不能误用旧缓存；当前支持测试无未解释失败。工程门未过，不比较新准确率。

## PR-01：统一答案合同、计分和诊断

**目的。**避免把答案提示变化误当成保留机制贡献。

**位置。**`direct.py::run_direct_full_context`，`subquery_runner.py` 最终调用和后处理，`agent_prompts.py::final_answer_prompt`，`metrics.py`；建议新增 `answering.py`。[C07, C11]

**具体修改。**

抽取 `solve_answer(question, evidence_bundle, contract, client, budget)`。同一证据包经过 Direct 与框架必须生成同一个请求。模型、thinking、输出上限、解析器和评分统一；Direct 与记忆方法的差别只在它们提供的材料及其构建流程。

删除“仅按证据”与“无论缺证据也必须猜”的冲突。缺证据时可以记录 INSUFFICIENT；标准可回答任务上仍按原指标计错。本版**不添加缺口补搜**。

数据入口分离 `InferenceInput` 与 `EvalAnnotations`。答案和支持标注仅供评价或明确标记的诊断 oracle，不能进普通计划、阅读或保留决策。题型专用后处理只作旧版指标，主比较使用统一规则。

完成四项诊断：支持原文 oracle；相同原文有/无旧绑定陈述；只在当前窗口供给支持句的抽取 oracle；相同候选/预算下的简单来源记忆。所有 oracle 单列，不计为方法结果。正常补救途径只有继续尚未完成的顺序阅读。

**验收。**M05–M09。同包同请求，gold canary 零泄露，错误状态不被覆盖，四组逐题差异有报告。语义指标没有“必须达到多少才算代码正确”的硬门；若 oracle 已差，应先检查数据与答案模型。

## PR-02：稳定来源与建立只按存活指针回看的入口

**目的。**保留原文核验，不引入全文检索。

**位置。**`cursor.py`，`manifest.py`，`archive.py`，`source_refs.py`，`memory_sources.py`；建议新增 `source_access.py`。[C06, C08, C12]

**具体修改。**

统一实际 tokenizer 计数。保留官方句界；raw 输入使用可靠的文档/字符区间，不在本轮重做“完美分句”。已有500-unit来源块称为 anchor，不把它们保证为自然句。

来源用稳定文档身份和原文半开区间表示；窗口号和文档展示顺序作为元数据。跨窗开放到哪里，权限就到哪里；不可一次 fetch 把同一锚点尚未读的后半段泄露出来。

提供接口草案：

```text
lookup_for_evidence(evidence_ids, purpose, budget, state_version)
```

调用者提交**存活 evidence_id**，运行时从记录解析来源；不接受模型随意提交任意 source_ref、整篇文档或搜索词。BIND 和 ANSWER 都走此入口。当前窗口新提案可使用短期授权，但窗口提交后授权失效，只有已保留条目继续有效。

邻域规则预先固定：同文档、已读、限定前后锚点数及总 tokens；不递归延展、不按答案缺口不断扩大。本版不调用 `expanded_context`。若额外邻域暴露了其他事实，允许模型利用本次合法可见内容，但记录为邻域提供，不能把该内容计成已保留候选；不得据此自动生成沿文档漫游的新指针。

来源内容改变导致 source_hash 失配时，拒绝使用旧绑定。原文不可被模型摘要覆盖。

**验收。**M10–M15。未读来源、任意猜测ref、被淘汰且无其他合法覆盖的来源均不能回看；来源可跨顺序稳定映射；固定邻域不可链式扩展。合法局部核验正常运行、开销被记录。

## PR-03：统一 hints 与 facts，取消唯一查询归属的入库门槛

**目的。**落实“先保留线索，后确认用途”。

**位置。**`working_memory.py`，`update_json.py`，`fact_protocol.py`，`subqueries.py::ingest/candidate_facts/route_candidates`；建议新增统一 retained evidence store。[C02, C03]

**具体修改。**

新 UPDATE 使用 evidence 数组，`candidate_query_ids=[]` 合法。对一个来源支持的线索，query不确定不影响其进入保留候选集合。

旧 facts 转为带 query 关联的记录；旧 hints 中具体来源线索转为未路由记录。纯粹“需要再找什么”的计划建议不得冒充事实，单独进入计费的 plan_notes，不能获得来源访问权。若旧hint混合了两者，保留原记录用于审计，明确标记未分类；只有可定位具体来源部分进入证据提案。

未知 query ID 不再导致整条有效来源丢失：去掉无效关联，作为未路由提案记录警告。无效来源、未读来源、空source仍拒绝。

记录身份与查询使用分离。某条记录被路由到另一需求时不重写正文、不会因为 query_id改变而生成新的事实副本。相同来源中的不同关系不得互相覆盖。

替换所有直接遍历 `state.facts` 的推理入口，确保只获得当前 live set；旧facts全量字典如用于历史回放，只在 legacy/audit 域可见。

**验收。**M16–M21。未路由导演关系后来可激活出生地需求；同一记录支持多需求；错误路由不删除有效来源；纯计划建议不能用于绑定；一个查询拒绝不会全局删证据。

## PR-04：把查询计划持续变成阅读需求，而不是等待执行的清单

**目的。**让 DORMANT 需求在目标实体未知时仍指导第一次阅读。

**位置。**`schema.py::Subquery/QueryPlan`，`plan_validation.py`，`subqueries.py::query_projection`，`agent_prompts.py::reading_prompt/reading_json_prompt`。[C09, C13]

**具体修改。**

保留自然语言查询与 depends_on/output，新增或派生 relation_cues、已知限制、未知输入等紧凑视图，不引入必须覆盖所有数据的固定关系本体。

例如：Q1寻找“电影A—导演”；Q2寻找“待定人物—出生地”，人物要等Q1确定。Q2可指导保留“B出生于X”，不能指导把B猜成导演。

每个阅读窗口收到：原问题、当前窗口、预算内有效记忆，以及当前/待解需求。对比 ablation 时只切换需求可见性，其他提示保持一致。已知实体是有据约束；未知实体不能用于过滤，别名不确定也不能直接判不匹配。

UPDATE职责仅限提出来源线索及可能关联，不发布confirmed答案。要求保存影响关系的否定、时间、身份和范围条件，但不要求把所有人物全部生平都抽出来。

计划修订只在当前原文或存活证据提示必要变化时触发；修订带来源依据和版本。新增需求可重新关联当前存活证据，不可回扫淘汰池或原文全库。初始机制实验可冻结计划结构，另做计划修订消融。

**验收。**M22–M25。下游需求在依赖未满足时出现在阅读视图；未知变量不被填成猜测实体；Q1明确后Q2实例视图与记忆同时更新；超长计划不能绕过预算；规划错误有未路由保留通道但不声称能完全恢复。

## PR-05：从“隐藏视图”改为真正受限的持久保留

**目的。**研究记忆管理本身，而不是无限候选库上挑选短提示。

**位置。**`subquery_runner.py::memory_text`，`subqueries.py::set_visible`，`working_memory.py`，状态存储与事件回放；建议新增 `retention.py`。[C04]

**具体修改。**

显式区分 `max_live_state_tokens` 与 `max_prompt_tokens`。原代码 memory视图隐藏不是持久淘汰。新的live state预算包括需求视图中的语义、线索、来源指针、关联、绑定值、尚在使用的冲突与语义缓存；其他存储另外报告bytes。

原文档案可持续增长，但没有全文语义查询权限；审计日志可无限留存用于分析，但运行时不能查它。不要声称整个系统总存储为常数。

先计算计划/运行中绑定闭包成本，再分配剩余候选容量。首版采用透明的覆盖优先策略：当前需求、待解需求、未路由探索三个预算槽；空槽可以借用。建议开发起点待解占30%、未路由10%，其余给当前需求；这些比例不是已验证最优值，正式比较前固定。

同一槽内按来源有效性、已知条件兼容性、去重复与主体多样性选取，再用稳定规则打破平局。关系/主体线索是候选排序信号，不是语义蕴含证明。不要用未经校准的模型自报置信度直接决定记忆生死。

按归一化需求去重，防止把一个需求拆十个节点抢十份配额。多需求共享同一记录，实际序列化只计一次正文，路由边单独计费。全部放得下时保留全部，不为制造消融差异强行删除。

有效绑定若要用于后续，必须同时保留其证明闭包或一个已计费、可合法回看的来源支持对象。不能无限pin住旧证据导致预算失效。闭包放不下时可淘汰绑定及依赖后代，或按预定义策略报告RESOURCE_LIMIT；不保留“知道值但没证据”的影子结果。

被淘汰记录从运行时线索、关联索引、可用别名、缓存语义与授权指针中同步移除。历史ID存在于审计记录不产生可用权限。同一内容以后在新的前向窗口再次出现，可作为新观察保留，并明确记为 REOBSERVED，不是从历史库找回。

**验收。**M26–M33。每次提交状态不超限；同输入确定性选择；所有记录可容纳时不丢失；隐藏不计成淘汰；共享来源不夸大信息丢失；绑定闭包不留悬挂值；只有日志中存在的事实无法重新进入推理。

## PR-06：重排阅读内循环，确保修改后仍是边读边记边更新

**目的。**避免先淘汰新桥接线索再绑定，也避免全部推理拖到EOF。

**位置。**`subquery_runner.py::run_subqueries` 中 UPDATE、ingest、maintain、process_activations 和snapshot顺序。

**建议流程。**

```text
初始化计划
for 每个前向窗口:
    构建当前/待解需求视图
    READ 当前窗口 → 来源提案
    校验、去重 → 本窗口暂存区
    对“旧存活记忆 + 本窗口提案”处理就绪依赖事件
    只从这两部分选候选；按其合法来源核验与绑定
    根据新依赖状态进行预算化保留
    清理失效绑定/语义缓存/指针权限
    原子提交live state，清空暂存区，游标继续前进
EOF:
    处理尚未完成的、输入有变化的就绪事件
    只从最终live state组织原文证据包
    统一ANSWER；不启动搜索、不重新阅读全文
```

临时提案区也有明确tokens/数量上限，不得保存多窗口而不计费。当前窗口内处理依赖的事件次数有上限，不能在相同状态下反复要求模型改答案。超出事件预算时保留尚待处理状态到下一次合法调度，不回看整个旧窗口。

提交时一次性维护保留集和有效依赖，避免先保留绑定再删除它的全部来源。若基线使用相同暂存容量/调度次数，机制比较更容易解释。

**验收。**M34–M37。同窗口的桥接与属性可形成有据结果；早期属性在未来桥接到达后从存活记忆接入；跨窗口暂存清空；与需求无关的窗口不触发无输入变化的重复审阅；EOF后游标调用数不增长。

## PR-07：把 RECALL 改为存活记忆内的有限候选选择

**目的。**保留原有RECALL思想，去掉全候选桶的无界LLM扫描，不引入文档搜索器。

**位置。**`subqueries.py::candidate_facts/admit_recalled/route_candidates`，`subquery_runner.py::process_activations`，`agent_prompts.py::lookup_prompt`。[C03, C05]

**具体修改。**

候选入口为：关联该需求的存活记录、符合关系线索的未路由存活记录、对同一已确定主体存在潜在冲突的记录。不能只看uses[qid]；也不能扫历史facts字典。

先用轻量、可解释的内存筛选缩小范围，必要时再让现有低层RECALL选ID。第一版不需要向量模型、BM25或新agent。实体无歧义地不匹配才可硬排除；模糊别名保留为不确定项。来源核验负责最终主体/关系判断。

明确限制每事件可呈现的候选数和tokens、每窗口召回调用数。排序遵循已知实体+关系+需求关联，并保留冲突候选，不只选最相似正面线索。截断时记录池大小、呈现数、未审阅数量与候选集合版本。

新桥接成立、新相关证据到达、原有输入被纠正才触发；读到无关窗口不再次扫相同桶。负面判断/无匹配仅对当前实例与候选版本有效，新证据必须能重新触发。

候选选择成功只记 RECALL_SELECTED，不设置 SUPPORTED。有限候选中只有一个值，不证明全文唯一；集合、否定和计数问题保留覆盖未知状态。EOF只关闭读取范围，不证明抽取及保留完备。

**验收。**M38–M42。任意未存活ID无法被召回；未路由桥接可被发现；召回总量受限；新证据更新后重审；选择结果不会直接写入绑定；记录截断不会自动宣布集合完整。

## PR-08：合并冗余核验，按具体查询实例延迟绑定

**目的。**减少错误确认和重复调用，保持原文是证据、摘要是组织。

**位置。**`memory_sources.py::prepare_memory_evidence`，`working_memory.py::SourceAssessment/BindingLink/QueryExecution`，`subqueries.py::apply_binding/invalidate`，高层 MEMORY/BIND 提示。[C10, C12]

**具体修改。**

高层一次接收已实例化子问题、上游支持、所选候选及受限原文，分别回答“线索忠实于原文吗”“原文支持当前主体/关系/限定吗”。不必机械串行叠加三次相同模型的VERIFY；合并版与旧版单独比较。

输出必须包含输入指纹、值、支持evidence_id、判定状态与必要限定。程序检查ID、已读范围、当前版本、父绑定可用性；模型判断自然语言支持。程序合法不等于语义一定正确。

候选cue有误但原文清楚时，可在同一来源范围内纠正cue或生成正确绑定，保留旧记录审计版本；禁止凭模型知识补值。一个事实有否定/范围信息时不压成无条件关系。

绑定成功后，同一事件同时更新B_t、计划实例化视图与工作记忆支持结构。上游值修订则使依赖它的后代失效，保留独立分支。失效的结果不能仅在界面隐藏，却仍从self.bindings中泄露给下一窗口。

cache key包含查询/计划版本、输入赋值、上游版本、候选版本、来源版本、实际可见邻域与模型/提示版本。重复语义输入不重审；网络错误不缓存为否定；被淘汰来源使相关cached语义失去可执行资格。

成员级归属不能含糊：相同输出值来自不同父路径时，支持路径分别记录；未实现完整成员组合前，最少不能把不同主体的属性合并后任意挑选。未完成集合覆盖保留为PARTIAL/UNKNOWN，而不是“所有值已找齐”。

**验收。**M43–M48。父亲/儿子日期混淆、反向关系、否定、同名、双值冲突均有mock结构回归和独立真实语义集。mock通过只证明状态处理正确；另报真实模型误绑定率。两个投影版本一致、后代失效正确、无新证据不反复改判。

## PR-09：最终答案只利用保留记忆及其原文，不要求图全部完成

**目的。**避免DORMANT/未绑定标签让仍存在的证据失去作用。

**位置。**`subqueries.py::final_evidence_pack/render_final_evidence_pack`，`subquery_runner.py` EOF分支，共享answering模块。[C14]

**具体修改。**

候选集合包含有效绑定的支持、相关未绑定存活证据、相关未路由存活证据以及冲突/限定。先从这些条目中按预算选支持组，再按授权指针装载原文。没有新发现通道。

已绑定结果用作导航，不作为压倒原文的权威标签；未绑定条目标为SUPPLEMENTAL_NOT_BOUND，不能被渲染成CONFIRMED。同源去重，相关桥接与属性成组，避免只保留叶子结果。

答案包包括raw_sources、supported_relations、unresolved_demands、conflicts。空需求或不完整计划不阻止答案模型根据已提供材料完成必要推理。引用只能来自实际展示的来源，邻域引用同时验证真实可见性。

移除“证据不够再检索一次”和“读取剩余所有原文”的兜底。EOF最多继续处理已经排队且有新输入的内部召回/核验，不新开搜索循环。最终缺证据如实记状态；可回答题计错。

主实验提供统一raw-first solver以隔离保留质量；另做带/不带关系提示的消融，不把额外推理提示收益全部算给保留策略。

**验收。**M49–M53。仍存活的未绑定出生日期可以进入最终包；计划未完成但原文充分时可作答；被淘汰且无合法覆盖的来源不可“最终兜底”；断链打包有诊断；最后一次模型调用之前没有任何搜索/全局重读。

## PR-10：闭合预算、事件和失败账本

**目的。**确保“记得更多”不是实际用了更多隐藏记忆和调用。

**位置。**`api.py::complete`，`storage.py::model_call_summary`，新source_access入口，所有agent调用，`metrics.py`。

**具体修改。**

分别限制：持久live state、单次完整请求、临时提案区、候选呈现量、局部回看累计量、模型总调用。请求包含system/schema/问题/需求/记忆/原文，预留输出和最终ANSWER资源。远程包装不透明则记录估算与provider实际usage，不伪称精确。

原文一次被BIND看到、一次被ANSWER看到，累计展示量算两次；同一次请求内去重后只计实际发送。保留唯一来源覆盖量作为另一指标。

模型逻辑调用、物理尝试、格式修复、网络重试、缓存命中分开。API失败无usage记录unknown，不填零费用。预算耗尽保留结果行与RESOURCE_LIMIT，不能排除出分母。

事件至少包括 EVIDENCE_PROPOSED、EVIDENCE_RETAINED、EVIDENCE_EVICTED、REOBSERVED、DEMAND_CHANGED、RECALL_SELECTED、SOURCE_LOOKUP、ASSESSMENT、BOUND、INVALIDATED、ANSWER_PACKED、BUDGET_BLOCKED。所有事件记录输入/来源版本、原因与前后预算。

新的运行期索引仅可从live set重建。断点恢复采用当前有效快照或完整事件回放到当前状态，不向模型开放历史淘汰内容；历史快照不是检索库。

**验收。**M54–M58。超限请求不发出；各入口账本可对账；故意一次失败后成功再缓存命中的测试计数正确；只在日志中的语义无法进入任何prompt；恢复后的live state与在线状态一致。

## PR-11：评测证据从读到、保留到使用的全过程

**目的。**让论文解释为什么有效或无效。

**位置。**`metrics.py`，离线支持标注映射脚本，受控轨迹分析脚本；不改推理权限。

**具体修改。**

用独立标注和固定文档顺序定义延迟证据和t*：支持后续关系的事实先出现，确定用途的桥接支持在更晚窗口完备。t*不能用某个方法何时绑定成功定义，否则失败方法会从分母消失。

分别统计首次捕获、cue记录存活、合法来源可达、需求激活后的候选召回、来源核验正确率、最终支持链覆盖、答案和成本。来源可达指标要计入真实固定邻域，而非只看fact_id；来源可达并不意味着候选能被正确选出。

延迟证据若始终没抽取，算捕获失败；抽取后淘汰算保留失败；仍存在但选不中算召回失败；原文充分仍误判算支持判断失败；最终证据完整但答案错算利用失败。多因并存可多标签，不能仅凭覆盖自动认定因果。

同一道题的顺序/长度变体按原问题聚合统计与bootstrap；保留逐题配对差异。分母为零输出NA，不补100%。标注映射不确定单列。

**验收。**M59–M62。人工五类失败轨迹能手算复核；同源cue淘汰但指针存活的例子不被记作不可达；桥接未绑定也计入原分母；gold只存在离线评测域。

## PR-12：按机制、端到端、系统参照三层推进论文实验

**目的。**验证主线，而不是挑选对自己有利的数据与约束。

**第一层：固定候选流的保留实验。**相同预测计划、相同抽取提案、相同容量/来源权限/solver，比较FIFO、仅当前需求评分、均匀需求覆盖、当前+待解需求保留。全部放得下不强制删除。共享提案由看过完整需求的extractor生成时，必须披露：该实验只证明保留策略，不证明抽取阶段收益。

**第二层：端到端MWR比较。**比较legacy_v08、flat_memory_mwr、新方法。分别移除待解需求阅读指导、待解预算、未路由通道、依赖触发召回、raw-first支持。一次只改一个机制。短文本无预算压力也报告，用于检查框架是否损害本来容易的问题。

**第三层：外部系统参照。**完整上下文Direct、正常配置的迭代RAG、既有概要回看或记忆方法可作为对照。RAG不接入本方法；也不禁止RAG按自己的方式建立索引。访问权限/索引容量不同，明确标作系统效果—成本比较，不声称完全等存储的单变量机制实验。普通提示词滚动记忆不能冒充原论文训练模型的完整复现。

数据先保留2Wiki诊断；再在已讨论的多跳数据和固定公开长问答子集开展验证。同题顺序变体保持相同文档集合，内部语义完整。证据间距、候选干扰、记忆容量是独立实验因素；不要只堆长度。先按原始题划分，再做变体。不能让两个顺序的同一道题落入开发与测试两边。

预注册主要预算、主要长度、主要比较和主指标。建议容量先做2k/4k/8k等pilot仅检查压力分布，实际值按模型和固定协议确定；这些不是性能承诺。最终不按谁赢来选择主条件。

**验收与决策。**M63–M66。预算、数据和模型合同相同；所有失败题保留；存在明确的保留压力且未达到所有方法都接近零的退化区；正式结果有配对区间。

工程必过：访问/标注泄露为零，预算与状态测试全部通过。

机制继续门：预先选定条件下，待解策略相对current-only有可复现的关键证据存活/可用性改善；具体最小实践差值可预设，不规定一个普遍的“论文需要涨5分”。

方法论文门：同预算准确率改善，或在预设非劣界内降低指定资源开销；二选一作为主目标提前固定。保留改善但答案未改善不能宣称问答提升。真实模型语义测试和bootstrap区间不能被mock测试替代。

## 四、第一版实现的最小范围

先完成PR-00～03，消除对照不一致、来源权限和候选孤岛；再做PR-04～06，使需求真正作用于前向阅读和预算化保留；之后做PR-07～10，形成有限召回、来源核验和统一作答闭环；最后完成PR-11～12的机制和正式实验。

## 五、贯穿所有步骤的最小示例

问题：电影《青岚》的导演出生在哪里？

窗口1：陈澈出生于海州。另有多位人物出生信息。

窗口2～N-1：干扰内容，使有限记忆确实发生竞争。

窗口N：电影《青岚》由陈澈执导。

预期：窗口1的需求视图已经包含“待定导演—出生地”；陈澈出生地作为候选保留，不提前断言他是导演。窗口N建立导演关系后，从当前live set召回出生地候选，按其指针核验，再形成出生地绑定。ANSWER看到导演关系与出生地原文。

负向变体：把出生地候选及所有合法覆盖指针确实淘汰后，再给窗口N。框架可以报告线索缺失，但不能从全文档案或日志“找回来”。若最终仍回答正确，须检查是否来自模型先验、其他合法来源或泄漏，而非直接判为记忆成功。

## 六、最终交付清单

源码提交与版本合同；访问与预算回归测试；统一诊断报告；live state与来源访问日志；逐题过程指标；固定候选保留消融；端到端结果；强对照与成本曲线；留出集和实验配置哈希。

最终需要成立的论证是：

**待解需求影响首次保留 → 相同容量下关键线索活到依赖明确 → 存活记忆内召回并按来源核验 → 最终证据链更完整 → 准确率或指定资源权衡改善。**

任何一段尚未得到实验支持，都应如实说明。方法的核心不在于原文能重新搜索到，而在于顺序阅读时更少忘掉后面真正需要的内容。
